# Portfolio Case Content Writing Guide

This guide is for writing future portfolio case-study content in English. It covers only case-study body content, section titles, captions, and stats. It does not define page layout, header copy, navigation, intro metadata, or visual design.

The writing direction is a symbiosis of three references:

- Parviz's current website voice: calm, precise, design-led, personal but not casual.
- ONY-style branding case writing: idea-first, focused on identity logic, system behavior, and visual meaning.
- AIC-style product case writing: task-first, focused on structure, user flow, interface decisions, and measurable clarity.

Use ONY as the stronger reference for branding projects. Use AIC as the stronger reference for product design and UX/UI projects. If a project includes both branding and product design, use branding logic for the identity sections and product logic for the UX/UI sections.

## Core Voice

Write like a designer explaining the work with confidence, not like an agency selling a service.

The tone should be:

- Clear, compact, and specific.
- Intelligent but not academic.
- Calm and controlled, with no exaggerated claims.
- Human enough to feel authored, but not conversational in a chatty way.
- Focused on why the design decision exists, not only what was made.

Prefer:

> The logo uses a modular structure to reflect the museum's collection of miniature books in different formats and scales.

Avoid:

> We created a unique, modern, and memorable logo that perfectly represents the brand.

## Before Writing A New Case, Ask Parviz

Ask these questions before writing content for any new case. Some answers may be unnecessary depending on the project, but they should be checked first.

1. What type of project is it: branding, UX/UI, campaign, motion, or hybrid?
2. What was Parviz's exact role, and what should not be credited to him?
3. Should the text use "I" or "we"?
4. What is the client or product context in one factual paragraph?
5. Who was the main audience or user group?
6. What was the main business, brand, or user problem?
7. What was the core design idea?
8. Which parts of the project should be explained deeply, and which should stay mostly visual?
9. Are there any constraints worth mentioning, such as time, platform, legacy identity, market, language, or production limits?
10. Are there verified numbers or stats? If yes, what exactly do they measure?
11. Are there things that must not be mentioned, such as collaborators, internal strategy, client restrictions, budgets, tools, dates, or unverified outcomes?
12. Are captions needed for any media, or should the visuals speak without captions?
13. Are section titles already decided, or should they be created from the content?
14. Does the project need a stronger conceptual branding explanation, a stronger UX/process explanation, or both?
15. Are there claims that need extra care, such as "first", "only", "largest", "leading", "award-winning", or "successful"?

## Branding Case Logic

Branding content should usually explain the relationship between idea, form, system, and application.

Strong branding writing answers:

- What is the core idea behind the identity?
- Why does the logo look the way it looks?
- How does the identity behave across different formats?
- What role do color, typography, motion, illustration, or layout play?
- How does the system make the brand more recognizable, flexible, or clear?

Good branding section types:

- Naming
- Logotype
- Logo System
- Color
- Typography
- Visual System
- Illustration System
- Motion
- Applications
- Campaign
- Guidelines

Branding paragraphs should not become a process diary. They should explain the designed logic.

Example structure:

```text
The identity was built around [core idea].
[Design decision] translates that idea into [visual/system behavior].
This gives the brand [practical effect] across [touchpoints].
```

Example:

```text
The identity was built around the contrast between precision and play. The logo uses a strict geometric base, while the supporting graphics introduce small irregular details that keep the system from feeling mechanical.
```

## Product Design Case Logic

Product design and UX/UI content should usually explain the relationship between task, structure, user logic, interface decisions, and outcome.

Strong product writing answers:

- What did the product or page need to clarify?
- What was difficult for users or for the business?
- How was the information structured?
- What interaction or interface decision solved the problem?
- How did the design reduce friction, improve understanding, or support action?

Good product section types:

- Task
- Context
- Information Architecture
- User Flow
- Website Structure
- Interface System
- Prototype
- Motion
- Content Logic
- Mobile Adaptation
- Results

Product paragraphs should not sound like generic UX language. Avoid saying "user-friendly" unless the sentence explains what became easier and how.

Example structure:

```text
The interface had to make [complex thing] understandable without [risk].
We structured the experience around [logic], so users could [action] without [friction].
```

Example:

```text
The website had to present several aviation and petrochemical services without turning the page into a technical catalog. We structured the experience as a single clear path, where each section introduces one service through a focused visual, short explanation, and enough space to separate it from the next.
```

## Hybrid Cases

For projects that combine branding and product design, separate the content logic by section.

Use branding language when explaining:

- Naming
- Logo
- Color
- Typography
- Brand assets
- Visual identity
- Campaign visuals

Use product language when explaining:

- Website structure
- Navigation
- User flow
- Interface decisions
- Forms
- Product logic
- Conversion or usability

Do not force one writing style across the whole page if the project has two different design layers.

Example:

```text
The brand layer gives the company a clearer voice and visual character. The product layer translates that voice into a website structure that makes the offer easier to understand and act on.
```

## Section Titles

Section titles should be short and functional. They should guide the reader through the case without trying too hard to sound clever.

Use titles like:

- Naming
- Logotype
- Visual System
- Website Structure
- Launch Phase
- Product Campaign TVCs
- Social Media
- Results

Avoid vague titles like:

- The Challenge
- The Magic
- A New Experience
- Making It Better
- The Journey

Only use a more conceptual title if it is genuinely part of the project's idea.

## Body Paragraphs

Use one idea per paragraph. Keep paragraphs compact enough to sit well inside the page's designed text blocks.

Good body copy usually follows this order:

1. Context: what the project is about.
2. Task: what needed to be solved.
3. Design idea: the main logic behind the work.
4. System or interface: how the idea became usable.
5. Result: what the design made clearer, stronger, easier, or more recognizable.

Not every case needs all five parts. Ask first.

## Captions

Captions should be quiet and useful. They should not compete with the main content.

Use captions to:

- Identify what the viewer is seeing.
- Explain a design detail that may not be obvious.
- Connect the visual to the system or user flow.
- Clarify a prototype, campaign phase, or media format.

Avoid captions that repeat the section title or describe the obvious.

Prefer:

> The modular mark adapts from a compact symbol to a wider horizontal composition without changing its basic logic.

Avoid:

> Logo design.

## Stats

Use stats only when they are verified and meaningful. Do not make weak numbers feel bigger with vague language.

A good stat block has:

- A large number.
- A short label.
- A small explanatory line.
- Clear boundaries, if needed.

Example:

```text
310K+
Launch films view count
without additional reach coming from influencers, partner pages, and third-party social media accounts.
```

Before writing stats, ask:

- What exactly does the number measure?
- What period does it cover?
- Does it include organic reach, paid reach, influencers, partner pages, or third-party reposts?
- Is the number rounded?
- Can it be publicly shown?

## What Not To Write Before Asking

Before writing any of these, ask Parviz first:

- Awards or recognitions.
- Client names beyond what is already public.
- Collaborator names.
- Agency/studio credit.
- Exact dates.
- Business results.
- Revenue, conversion, sales, or growth claims.
- "First", "only", "largest", or "leading" claims.
- User research claims.
- Technical implementation details.
- AI/tool usage.
- Internal strategy.
- Anything confidential.
- Anything that changes the perceived authorship of the project.

## Avoid These Habits

Avoid generic phrases:

- seamless experience
- innovative solution
- cutting-edge design
- user-friendly interface
- visually appealing platform
- modern and clean design
- unique and memorable identity
- strong brand presence
- engaging visuals
- premium look and feel
- intuitive navigation

These words are not banned forever, but they must earn their place. If a sentence can stay true without them, remove them.

Avoid weak structure:

```text
The challenge was to create a modern website for the brand.
```

Prefer:

```text
The website had to make all company services understandable on one page without flattening the technical nature of the offer.
```

## Useful Sentence Patterns

Branding:

```text
The identity was built around [core idea].
```

```text
The logo uses [formal decision] to express [brand trait].
```

```text
The system stays recognizable because [repeatable rule].
```

```text
The color palette separates [category/state] while keeping the brand visually unified.
```

Product design:

```text
The page had to make [complex offer] clear without [risk].
```

```text
We structured the experience around [logic], so users could [action] without [friction].
```

```text
The interface uses [layout/content pattern] to make [decision/action] easier at the moment it matters.
```

Hybrid:

```text
The brand system creates [recognition/voice], while the product layer turns it into [navigation/action/interaction].
```

## Review Checklist

Before considering case content finished, check:

- Does every paragraph explain a real design decision?
- Is the project type reflected in the writing style?
- Are branding sections concept-first and system-aware?
- Are product sections task-first and user-logic-aware?
- Are claims specific and provable?
- Are stats clearly defined?
- Are captions useful and quiet?
- Are section titles short and functional?
- Are line breaks and text block widths respected in the coded page?
- Is there any generic agency language that can be removed?
- Did Parviz approve all sensitive claims, names, credits, and numbers?
